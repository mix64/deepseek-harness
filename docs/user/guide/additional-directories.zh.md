# 在工作区之外写入

[English](additional-directories.md) | 中文

## 概述

在 **工作区内修改** 模式下，会话只修改其工作区内的文件。当任务还需要修改其他位置的文件时，例如相邻的仓库或共享库的检出目录，可以为会话添加更多目录。每个会话保留自己的目录列表。

## 添加目录

1. 在 composer 的权限选择器中选择 **工作区内修改**。其他模式会保留该列表，但不授予任何权限，目录控件会显示 **当前模式下不可写入**。
2. 打开权限选择器旁的 **添加目录**。添加第一个目录后，它显示为 **目录（n）**。
3. 选择 **添加目录…** 并选取一个文件夹，或在 **工作区** 下选择一个已注册工作区，单击即可添加。

该目录会出现在菜单中主工作区的下方，对话中也会记录 `/add-dir` 命令。在 Windows 上，为大型文件夹授予访问权限可能需要数秒；完成之前，控件显示 **正在授予访问权限…**。

## 使用斜杠命令

输入 `/add-dir <dir>` 添加目录，`/remove-dir <dir>` 移除目录，单独输入 `/add-dir` 列出目录。含空格的路径可以直接输入；以 `"` 开头的路径必须是一个 JSON 字符串，例如 `/add-dir "D:\\shared lib"`。相对路径相对于工作区解析。

## 无法添加的目录

目录满足以下任一条件时会被拒绝，原因显示在控件旁：

- 是文件系统根目录；
- 是工作区本身、位于工作区之内，或包含工作区；
- 与已添加的目录重叠；
- 是临时目录或包含临时目录，例如 Windows 的用户配置文件目录；
- 会超出会话 16 个目录的上限，部署方可以修改该上限。

## 新会话与子 agent

在同一工作区中新建的会话以当前会话的目录启动。无法沿用的目录（例如已不存在的目录）会在提示中列出。子 agent（智能体）与 fork 以父会话的目录启动；在其他工作区中新建的会话不带任何附加目录。

## 移除目录

打开菜单并选择该目录所在的行，或输入 `/remove-dir <dir>`。文件夹中的文件不受影响。在 Windows 上，文件夹会保留 DSH 添加的访问条目，之后的会话不再使用它；[Windows ACL 参考](../../../packages/sandbox/sandbox-windows-acl/README.zh.md#known-limitations-and-deferred-work)说明了这种残留。
